# 开发前最终对抗性审查

> 历史调查/审查材料：事实与证据保留，本文原有实施建议、旧功能范围和验收工作包不作为当前要求。当前只做网页 IM 范围及唯一扩展“独立强提醒窗口”，以[当前范围决定](../decisions/2026-10-30-web-only-scope.md)为准。新方案尚未因此获得原型或发布验收。

2026-10-30 · Asia/Singapore

**结论：文档可以作为受约束的开发起点；可以进入基础工程与关键路径原型阶段，尚不具备全部功能方案冻结、直接铺开实现或上线的证据。** Tauri 2 + Rust 仍为首选候选，IM 传输继续通过共同契约比较 Web SDK 与 Node sidecar。不能用一次文档审查替代目标运行时中的登录、发送、恢复、安装和数据保护验证。

本轮覆盖开始时全部 22 份项目 Markdown、4 份已有证据 JSON、架构配图与相关客户端源码指纹，随后增加了两份可复算的网页证据。第三方分发包中的许可证和运行清单作为来源材料检查，不作为自有设计规范改写。六路子审查分别负责架构、账号/存储/网络、窗口/提醒/媒体、业务页/更新/助手、IM/网页实测、独立证据审计；主审统一公共契约并交叉检查。保留工作区已有调查与改动，没有实现产品功能、执行部署或提交 Git。

## 1. 第一性原理：必须守住的事实

1. **每个操作属于确定的身份。** 账号、部署环境、登录代次、会话和来源视图必须在操作创建时固定。切换当前账号不能改变在途请求的归属。
2. **发送是有外部副作用的事务。** 本地超时不能证明服务端没有接收；服务端幂等未验证时，不得自动换通道重发，也不能承诺 exactly-once。
3. **完整性不能由“最新一条”推导。** 见过 M3 不代表已有 M2；必须区分最新已见水位和完整同步水位，并证明分页、乱序与中断恢复的终止条件。
4. **提醒必须基于真实待处理状态。** 打开会话、已读、本地收起提醒、商家回复、会话结束是不同事实。睡眠恢复后先对账，再决定是否提醒。
5. **页面和系统集成都是可能失败的边界。** 远程页面不是可信本地代码；框架 capability 不是业务对象授权；同属 Chromium 也不证明嵌入式登录、Profile、通知或后台保活成立。
6. **本地唯一数据不能被当缓存处理。** 草稿、outbox、未知发送结果、账号归属与迁移进度必须可恢复。迁移重试不能清正式库，旧备份恢复不能导致重发或串号。
7. **性能收益需要同条件对照。** 不携带 Electron 不等于没有浏览器进程，也不保证内存减半。短时高 CPU、进程数和网络请求数不能单独证明瓶颈原因。

## 4. 开发准入与验收关口

“G0”是下面 G1–G5 的可行性阶段名称，不是额外技术功能。测试中涉及消息发送、状态切换、故障注入和升级，使用专用测试账号/会话与隔离安装产物；本轮未执行这些动作。

| 关口 | 当前状态 | 通过条件 | 未通过时可做/不可做 |
| --- | --- | --- | --- |
| G1 身份与隔离 | Ego官方登录有证据；目标WebView2未验证 | 正式目标运行时登录、两账号隔离、正确业务成功判据、Cookie恢复/失效、退出重登迟到结果拒绝 | 可做账号状态机和mock；不可宣称网页登录/Profile方案已经定型 |
| G2 页面与桥 | 静态入口和桥已盘点；安全模式兼容未验证 | 8业务入口、microApp、带POST的新窗口、上传下载、焦点/DPI、来源鉴别、崩溃后隐藏视图恢复 | 可做窄桥与外壳；不可对全部线上页面承诺原样兼容 |
| G3 IM正确性与传输 | WSS连接和自然入站有证据；发送/恢复闭环未验证 | 测试会话文本/附件/引用/回执、unknown、localId语义、分页补拉、双账号、断线/睡眠、状态回读；Web与Node同场景比较 | 可做ImTransport、outbox与夹具；不可固定最终传输或自动重发不确定消息 |
| G4 安装与系统集成 | 设计修订完成；正式产物未验收 | 干净普通用户环境Runtime、OCR部署身份/引擎、通知激活、独立深链、监视器、离线安装和卸载 | 可做平台原型；不可按开发机现状宣布可交付 |
| G5 数据与发布 | 设计修订完成；故障验收未执行 | 双账号备份/错配拒绝、导入失败保留新数据、磁盘不足、更新前排空、签名策略/重放拒绝、schema兼容与恢复 | 可做存储与更新状态机；不可拿真实用户库进行覆盖迁移或发布未经验证升级 |

先做 `contracts`、身份生命周期、事件/快照协议、存储边界和可替换传输，同时推进上述关口。关口通过后冻结对应适配器与接口；失败则按架构文中的备选路线调整。UI布局、主题等不依赖未决平台能力的工作可并行。原文各模块人日没有覆盖所有新增故障验证、联调与发布成本，不作为最终交付工期。

每个关口的验收记录至少包含：应用/SDK/页面与运行时版本、平台、测试身份类别、动作与故障点、期望、实际结果、脱敏证据文件、失败后的决策。`passed`、`failed`、`blocked` 分开，不能用“接口已找到”或“代码已写”代替 `passed`。
