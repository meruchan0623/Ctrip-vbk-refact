## 实现

macOS 使用受控 Tauri 2.12.5 补丁修复全局 terminate 回调按标签查找新实例的风险。每次创建在 PreparedWebview 中直接携带独立资源身份，经子视图和顶层窗口两条创建路径传到 attach；终止回调用 Weak 与指针身份核验。创建前后迟到的旧回调不能作用到同标签的新实例。创建完成前的终止信号和应用初始化完成前的终止信号分别保存在具体实例内，挂接及显式 ready 后消费，不依赖定时猜测。上游双许可证、版本和 143 个原始文件的哈希保留，只改三个上游源文件，新增共享身份测试；Cargo metadata 已确认使用本地补丁。

Windows 的 renderer/browser 早期故障也先存入具体实例的有界状态，READY 后才访问账号和适配器。browser 故障优先，重复同实例故障不会反复提升账号代次。完整 Windows 浏览器环境重建、监听注册失败提示、未响应及 GPU 阈值规则仍待补齐。

会话读取失败时保留同账号当前缓存并显示重试；成功空数组才清空。首次失败、畸形响应、并发读回和账号代次变化均与空列表区分，不能用旧失败覆盖新状态。

AdapterBridge 改为有界 FIFO（默认含在途最多 1024），计数饱和且旧代次待发送项明确取消。过载后停止该页面入站与 SDK 自有监听，锁存终态，不自动重连抢占或重放发送。固定 bridge_fault 控制信号绕过满队列，复用 adapter_push_fact，在宿主按账号、视图代次及最新 READY 租约验证后退出在线，保留已有凭据、Profile、草稿和 unknown 发送账本。没有保存凭据的账号按既有退出在线语义成为 LoggedOut。控制信号不进入 IM 核心游标，也不伪造鉴权失效。远端权限仍为五个命令加两项事件权限，未放宽门禁。

## 审查发现

已修创建前终止漏消费、迟到 plugin-ready 覆盖新实例、Windows 初始化前访问未建立状态、队列过载误当继续正常运行、旧 READY 迟到覆盖新租约、旧身份回调恢复已暂停账号等边界。补偿水位由成功应用的 CompensationSync 才推进；部分批次过载不凭未投递队尾推进持久水位。合法全量快照使用背压而非触发过载，等待者最多五个，实时流保留队列余量。独立审查又复现首条消息 invoke 拒绝后 Sync 越过失败项推进水位，以及两种列表整批交错导致第二次 full Sync 误判会话缺失；现已增加批次前缀/Sync 双 ACK 屏障与同会话流整批串行，独立复测已用真实 adapter 输出喂当前编译的 core-im，确认两项缺陷消除；桥接/批量压力 26 项及宿主租约/通知 6 项、控制边界 2 项均通过。当前代次提交失败通过 delivery_failed 控制事实明确暂停，宿主显示“消息同步失败，已暂停，请重新登录”，与过载提示区分。正常 applied=true 的恢复提示、合法重复及旧代次回包不误判为投递故障。
