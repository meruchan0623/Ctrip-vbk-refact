## 可复现证据

### 浏览器工作量

Mac 上 Ego Chromium、Windows 样式、4 倍 CPU 降速、20,000 条合成消息、阅读历史中部、10 次草稿更新。两版都只挂载 22 行。

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 消息行 getBoundingClientRect | 440 | 0 |
| getComputedStyle | 440 | 0 |
| 新建 ResizeObserver | 10 | 0 |
| createElement | 2,568 | 1,820 |
| 套餐 host 跨更新保持同一节点 | 否 | 是 |
| 阅读行/相对偏移跨输入变化 | 不变 | 不变 |

额外验证：挂载行延迟增高 160 px、窗口缩窄及恢复后，阅读锚点均保持 `m:perf-10001`、偏移 `-58.5625 px`；套餐第二页按需构造，输入后仍选中且 host 复用；切另一账号草稿为空、旧卡片脱离 DOM，切回原账号草稿恢复。没有观察到页面运行时异常。

本次采样的 ScriptDuration 为 0.616 → 0.554 秒，TaskDuration 为 4.561 → 5.327 秒，LayoutDuration 为 0.100 → 0.134 秒。采样包含自动化和等待开销，工作区同期也有其他改动，不能据此宣称整体帧率或端到端耗时提高了某个百分比；工作量计数与独立算法测试是本轮主要证据。

### 算法与请求

- 20,000 条不变消息：首次建立锚点后，10 轮 plan/sync 不再扫描 sender_role；客户语言等派生结果有同类访问计数测试。
- 30 行稳定列表：后续相同列表/角色缓存命中新增 conversation IPC 为 0；30 gid、60 次成员/备注请求峰值并发为 4。
- 后台 30 会话且每个成员/备注请求各 1 秒：立即打开排尾会话约 4 秒开始并完成历史读取，避免超过宿主 15 秒超时。
- 旧未读批次挂住后停止/重启，新运行在合成时钟 100 毫秒内更新；旧批次不会继续占据新运行或发送剩余 gid。
- 2,048 行有序索引尾追加仅一次顺序比较；头部历史插入查找不超过 14 次比较。Vec 移动仍是 O(n)，未声称插入整体为 O(log n)。
- 套餐 fake DOM 计数：10 套餐×100 CDR×100 次相同 render，展开构造 90,300 → 138，折叠 90,900 → 49。该数据不含真实布局时间。

提醒覆盖 release 微基准（合成输入，不是应用总耗时）：

| 客户消息 × 回复 | 原逐对扫描 | 聚合 |
| --- | ---: | ---: |
| 1,000 × 1,000 | 1.191 ms | 0.149 ms |
| 5,000 × 5,000 | 26.679 ms | 0.522 ms |
| 10,000 × 10,000 | 122.662 ms | 1.192 ms |

最后一组由 100,000,000 次逐对 coverage 调用变为 10,000 次回复边界解析。默认覆盖计算期望 O(N)，另计 outbox 查询；逐条导入仍会累计遍历既有记录。

复现命令（在 `vbk/`）：

