# 开发范围调整：以网页版为准

2026-10-30，Asia/Singapore。状态：用户已明确决定，覆盖此前按桌面客户端功能对齐的方案。

## 当前决定

1. 不再跟随旅游商家桌面版实现，以当前网页版的真实入口、请求与行为为依据。
2. 业务功能只做消息、通知，以及必要的“按订单号找到客户并打开会话”。
3. 网页版没有的功能全部不做。桌面包里的接口名、共享代码中的未启用分支、默认设置字段，都不能单独成为开发任务。
4. 事件、公告、商服、产品、完整订单管理、数据、点评、工作台、首页均移出本项目功能范围；不再重建这些页面及其内嵌浏览器、菜单墙、角标和桥接能力。
5. 订单只保留服务聊天需要的最小入口：输入完整订单号、查询订单、打开详情或取得网页提供的联系入口、进入正确会话。不承接确认、退款、核销、导出等订单操作。
6. 设置仅保留目标网页实际提供、且服务消息/通知所需的部分。登录、鉴权、身份隔离和必要的交付基础设施仍需完成，但不能借此恢复桌面版独有的产品功能。

## 原方案的处理

| 原有内容 | 当前处理 |
| --- | --- |
| 消息、会话、通知、客服个人设置 | 按目标网页实际能力逐项确认；已找到接口不等于写入行为已验收 |
| 网页消息横幅、标题闪烁、浏览器通知、消息提示音 | 网页已有，保留其语义和权限限制，见[提醒调查](../research/2026-10-30-web-reminders.md) |
| 独立回复超时强提醒窗、持续置顶、循环声音、分级升级、贪睡、托盘预览 | 当前网页未形成可用的对应闭环，取消原桌面版对齐与自行扩展方案 |
| 通知分类“特别关注”、右键设置通知声音 | 当前新版网页明确禁用这些控制，取消；不能因为共享代码里有菜单就实现 |
| 多账号桌面标签、全局快捷键、窗口池、独立截图/OCR/纠错、桌面 SDK sidecar | 不再按桌面版移植；没有目标网页能力证据的项目取消 |
| 客户端专属更新源、携程崩溃上报接入、业务菜单配置 | 从业务接口缺失待办移除，不作为消息/通知开发的前置任务 |
| 原有各模块文档和开发计划 | 保留作为历史设计参考；其中超出本决定的任务、验收项和“必须实现”表述失效 |

这里的“取消”是取消本轮产品要求，不是声称携程所有账号、业务线或其他网页版本永远没有该能力。后续若目标网页出现真实入口，应先补页面与接口证据，再明确调整范围。

## 订单与网页版本

本轮同时遇到新版 `vbooking.ctrip.com/vbk/im/main` 与订单实际跳转到的 `imvendor.ctrip.com/main`。两者都属于网页，但构建、UI、部分参数和轮询实现不同，不能把它们当作同一个部署。

已走通两条路径，详见[订单会话调查](../research/2026-10-30-web-order-conversation.md)：

- 订单列表 → 完整订单号查询 → 详情 → “IM 联系” → `14361/createimchat` → 返回的 IM URL → 客户会话。
- 新版消息页 → 输入订单号 → 查询结果 → 会话历史 → “开始聊天” → 当前会话输入框。

新实现优先使用目标网页已验证的链路。不得仅凭订单号自行拼接客户 UID、群号、业务线或供应商身份；不得把订单查询当作已取得联系客户的权限。

## 强提醒结论

用户手动切为在线后，本轮继续观察了 45 秒自然流量，未出现回复超时强提醒弹窗；此观察没有控制未回复消息的角色、时长和条件，不能单独证明该功能不存在。

进一步读取当前新版网页代码确认：它仍保留 `checkConvTimeout` 计算与 `reply_timeout` 事件，但网页适配器的 `sendCommonEvent` 只处理 `openExtraWindow`，没有处理 `reply_timeout`。当前网页的普通提醒由消息事件、本地声音、标题闪烁和浏览器通知完成，没有发现单独的强提醒业务接口。故不恢复旧桌面版 alarm 窗口或自建更强提醒。完整证据与边界见[提醒调查](../research/2026-10-30-web-reminders.md)。

## 后续验收原则

- 每项能力需注明具体网页版本、真实入口、方法、请求字段、返回业务结果和 UI 读回。
- 静态代码只能把“未知接口”改为“已定位、未动态验证”，不能据此宣称可用。
- 发送、结束、转接、星标、评价等写操作的失败、权限与重复提交行为仍需对应样本；不因本次探查已打开会话就视为全部通过。
- 不为取消的功能继续补接口、造本地替代功能或保留默认启用的扩展。
