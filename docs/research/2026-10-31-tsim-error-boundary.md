# TSim 外部错误的本地 IPC 边界

登录、退出、翻译和既有 ICCID 查询原先将 `AppError.detail` 原样转换为前端 DTO。真实解析器会将上游失败响应的 message/msg 放入该字段；即使界面只显示固定提示，原文仍可能跨越宿主边界。

本行为增加 assistant 专用映射：只保留允许的错误码、固定提示与原来的 retryable；未知错误码也映射为固定服务不可用码，移除 detail。命令权限检查使用相同出口。全局 DTO、HTTP、会话和系统凭据库语义不变。

回归直接调用登录、profile、刷新、退出、翻译和套餐的生产解析器；先断言合成秘密确实进入原始 error.detail，再验证序列化后的公开 DTO 没有原文。既有失败映射的真实红例已退出101，恢复安全映射后通过；只使用合成标记，没有真实凭据或请求。

主代理从基线 ece045a 独立抽取两个安全文件及调用点，没有混入订单功能；checkout-index 快照 npm ci/bundle 和 Windows 宿主142项通过，0失败/ignored。独立评审确认这两个文件无未修P1/P2。此结论是代码与离线边界验证，不能代替用户正常登录后的线上验收。

命令日志位于本机临时目录 `vbk-windows-20261031/r7-public-error-*.log`；原始运行日志和包不入Git。
