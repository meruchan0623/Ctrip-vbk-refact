# 会话列表对齐与未读恢复修复

2026-11-04。本轮依据本机官方发布脚本及 [核查报告](2026-11-04-conversation-list-parity.md) 实施。保留公司名移除、80px行高、状态后产品名渐隐和三栏可调的布局。

## 四个列表缺口

- `parseLastMessage` 支持原始 `message` 及官方 normalized lastMessage，详情接口的 message 在身份校验后进入缓存和预览，即使未读数没变化也更新摘要。
- 处理中会话已有摘要也后台刷新，按官方读取最近20条、5秒请求超时并选择最后非空可展示摘要；并发最多2。已结束会话的空摘要继续做限频恢复。后台读取不创建聊天串展示、不发送已读回执。
- 排序仍置顶优先，最新消息时间缺失时回退更新时间；内嵌消息createTime进入列表时间投影。
- 摘要补语音、位置、卡片及订单/问答/商品/内容等action，文字、文件等按官方摘要规则。SDK、补偿和后台读取都能更新列表摘要；这不代表已新增完整语音/位置聊天组件。订单卡的方向隐藏与协议隐藏继续生效。

## 红点根因及修复

此前只从列表最后一条客户消息建立已读游标，最后为自己/系统时无法找到可确认的客户目标；回执成功只更新气泡，列表计数不收敛。

现在同会话、同房间、线程不冲突、不过当前权威上界且不跨已观察服务下界的已展示历史，可以恢复客户游标。合法迟到SDK客户消息也沿相同边界恢复目标；UI仍要求目标确实挂载且位于可见区域，后台预览不触发已读。

精确目标确认成功后更新本地未读数并主动读回服务端。确认水位防止延迟详情计数复活红点。新客户消息到达版本与证据必须被当前客户目标覆盖；旧回执不能清掉未纳入目标的新消息，包含SDK先到/请求飞行中到达、同时间不同消息ID等情况。
