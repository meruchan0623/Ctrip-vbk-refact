# 03 独立回复超时强提醒窗口

2026-10-30。状态：本项目自有能力，保留；实现方案已定义，代码已落盘到 `vbk/`（见 §8），尚未实机验收。它替换旧 L0–L4 全面提醒方案，边界见[范围决定](../decisions/2026-10-30-web-only-scope.md)。

## 1. 方案与证据

2026-11-03 调整：alarm 列表条目单击即打开对应客户会话，Enter/空格同样生效，清除按钮独立操作。新消息 L2 由宿主自绘的 `notice` 窗显示（2026-11-04 调整，替代系统通知：不依赖系统权限、签名与安装位置）：透明、置顶、不可获得焦点，固定在工作区右上角；卡片渐显并同步播放一次提示音，后到的往下排，消失的卡片淡出、其下卡片上移，同会话合并计数并重置计时，停留 6 秒，悬停暂停（最长 60 秒），最多同时 5 张，超出时最旧的退出。主窗在前台但未显示该会话时同样弹出；主窗聚焦且正在显示该会话时不弹（main 经 `notify_set_viewing` 上报）。只接受新插入的实时客户业务消息；新会话首条消息到达时发送者或会话归属往往未知，宿主暂存消息标识（不含正文），待会话列表与角色确认后补发一次，到达时不允许提醒或 30 秒内未确认则不再补发；重复、历史、初始化、补偿与系统消息不弹新消息通知。会话须 active 且在群内（`inGroup=1`），不在群内的会话不触发新消息或超时强提醒，退群后结束提醒轮次。`isOwner` 不参与判定：网页 `rF` 不看此字段，实抓的 144 条处理中且在群内的会话全部为 `false`。在线/挂起且服务端已确认时允许提醒，离开/下班、状态未知或在线状态租约过期时静默；恢复在线不补发旧新消息通知。系统勿扰继续生效。2026-11-04 调整：卡片只显示客户名称（与主窗会话列表相同，未补全资料前可能是客户标识或“访客”）和最多两行最新消息预览，同会话 2 条及以上时显示数字角标，不再显示铃铛、固定标题、时间和脱敏串；正文例外见第 6 节。

通知中心分类可单独开启横幅（2026-11-04）：`通知` 页右键分类选“使用横幅提醒”，设置按账号存入 `prefs.json` 的 `notice_banner`，分类名旁显示铃铛。网页没有可用的通知中心实时通道，开启后宿主经 `notice.watch` 每 30 秒读一次 `getIQConversations`（未开启任何分类时不发请求），分类的 `lastMsgTime/lastMsgId` 前进后再读 `getIQMessages` 确认并取标题，用同一个 `notice` 窗显示卡片并响一次新消息提示音；点击卡片切到对应账号并打开该分类。只读，不标已读。开启、启动或重新登录后的首次读取只建立水位，不补弹旧通知。遵守勿扰与系统静默、锁屏不弹且不补发；不看坐席在线状态，主窗正显示该分类时也弹。忽略分类会同时关闭它的横幅。真实新通知下的触发尚未实机验收。通知列表按时间从新到旧排列。

本地编译与合成回归用于检查接线和规则；真实新消息下的浮窗展示、点击跳转和提示音仍须实机验收。macOS 透明窗口需要 `macOSPrivateApi`（`macos-private-api` 特性），不影响公证，但不能上架 Mac App Store。下表中的旧 L2 横幅描述由此调整替代。

通知卡片点击携带 `account + session_generation + gid`，由宿主重新核对当前账号代次、会话归属和群成员状态，再显示/取消最小化/聚焦 main，发送已有会话定位事件；main 自动切换至对应账号并打开客户会话。不依赖超时提醒轮次，注销重登前的旧通知及已转出的会话不导航。

网页已有 Web IM 消息、`16037/getConversationList`、历史/补偿接口和本地 `checkConvTimeout` 计算。当前新版网页计算后发送的 `reply_timeout` 在浏览器适配器没有处理，不能直接调用它得到独立窗口，也没有已证实的专用强提醒后端接口。

因此采用 **网页消息/会话事实 → Rust 本地等待计算 → 一个独立 alarm 窗口**。这是本项目新增展示能力，不冒充网页或携程平台提供的强提醒服务。证据见[网页提醒调查](../research/2026-10-30-web-reminders.md)与[静态摘录](../research/evidence/web-message-notice-static-20261030.json)。

## 2. 功能：分级升级

默认等待阈值 T1 = 30 秒（可选 30/60/90/120/180），是本地产品默认值，不是平台 SLA。

| 级别 | 触发 | 表现 | 退出 |
| --- | --- | --- | --- |
| L0 静默计数 | 任何未读变化 | 托盘提示文字、任务栏未读数字（1–99，超出 99+）、托盘悬停未读预览 | 未读归零 |
| L1 闪烁 | 新消息且主窗口不在前台 | 托盘图标 500 ms 闪烁，任务栏闪烁 | 主窗口获得焦点 |
| L2 横幅 | 新消息，除非正在看该会话 | 独立 `notice` 浮窗卡片 + 一次提示音；同会话合并计数，停留 6 秒，悬停暂停 | 6 秒隐藏，点击跳转或关闭 |
| L3 强提醒窗 | 本轮首条未回复客户消息等待 ≥ T1 | 独立 alarm 窗置顶、不抢焦点，显示会话、最新消息预览、等待时长（> 90 秒标红），超时音一次 | 服务端确认有效商家回复、会话结束或转出 |
| L4 持续强提醒 | 用户开启（默认关）；进入 L3 后再过 T2 = 60 秒 | alarm 重新置顶一次，提示音每 15 秒循环，最长 10 分钟，之后只保留窗口与闪烁 | 同 L3，或“清除” |

- 升级只在级别变化时执行一次置顶；单纯计时刷新不反复抢置顶。
- **稍后提醒已移除**（2026-11-04）：alarm 不再提供入口，宿主也不再暴露 `notify_snooze` 命令。`core-notify` 仍保留贪睡逻辑和持久化字段，此前已贪睡的轮次到期后照常恢复。
- **清除 / 全部清除**：只隐藏当前等待轮次，不当作已回复；同一会话下一次有效客户消息开启新轮次后可再次提醒。
- 已读、打开会话、点击发送、发送中和发送结果未知都不能结束等待。
- 勿扰：托盘“勿扰 1 小时 / 直到明天”关闭 L1/L2 与提示音；“勿扰时仍提醒回复超时”默认开启，L3/L4 照常。全屏应用时 L2 同样使用 `notice` 浮窗，L3 是否显示由“全屏时仍弹回复超时”（默认开）决定。
- 会话列表读秒：头像下方胶囊按 `mm:ss` 每秒刷新（满 1 小时为 `h:mm:ss`），只读本地等待轮次。颜色分段：0–30 秒绿、30–60 秒黄、60–90 秒橙、90–120 秒红（与 alarm 标红阈值一致）并呼吸、120 秒起深红并呼吸；起点待核对时用虚线边框。
- 设置项：回复超时提醒开关、T1 阈值、超时提示音、持续提醒 L4、弹出位置（右下/左下）、勿扰相关开关、托盘闪烁、任务栏数字。
- 提示音只由宿主经 `notify://play-sound` 用 WebAudio 播放：新消息音在 `notice` 窗（与卡片同步），超时音在主窗。官方页（`acct-*` 与内置浏览器标签）的 `<audio>` 只能由用户手势启动，官方提示音因此不发声，也不会进入系统“正在播放”。

## 3. 消息与事实来源

复用当前网页消息通道与已有初始化、历史/增量补偿。适配器输出 `{account,session_generation,stream,epoch,seq,gid,messageId,createTime,senderRole,eventType,deliveryState}` 等必要字段；成员、会话责任与状态来自同一身份下的服务端快照。

只允许受控适配器向 Rust 发送有界、类型化事件；远程网页不能直接调用通用本机命令。事件来源和代次必须由宿主校验，不能信任载荷里自报的账号。主界面与提醒共享同一份消息事实，不再另建一条提醒专用 SDK 连接或高频接口轮询。

**原型前置**：证明 Web 消息接入在预期 Origin、Cookie 与宿主环境可工作，确认初始化/实时/历史事件能区分。若只能靠不稳定 DOM 抓取文本，不能直接进入正式开发；先落实可版本校验的 Web SDK/页面适配契约。不得为绕开问题切回桌面 SDK。

## 4. 等待轮次

以网页 `rF` 判定为参照，并用受控样本确认具体角色和消息类型：

1. 会话须处于可服务状态且当前坐席在群内；结束、已转出或不在责任范围的会话不提醒。BOP 等网页计算排除的类型不擅自纳入。
2. 只按成功的有效业务消息判断；机器人、携程客服及系统事件不能默认视为有效商家回复。未知角色或失败状态先同步，不猜测。
3. 客户连续发送多条消息时，以本轮最早可确认尚未被有效商家回复截断的消息为等待起点，不随每条消息重置期限。
4. 收到服务端确认的有效商家回复，或快照确认会话结束/责任转出后，结束该轮等待。其他商家坐席回复按网页角色语义验证后同样处理。
5. 点击消息、已读、打开会话、点击发送、发送中和发送结果未知，都不能结束等待。
6. 历史重放与重复消息不能重新启动旧轮次；乱序消息先按服务端顺序/回读重算。历史窗口不足以找到本轮起点时标为“待核对”，补拉后再确定，不捏造首条时间。
7. 租车 `CAR_TIMEOUT` 是网页中的单独分支；未验证的业务线规则不直接用于当前门票/活动样本。

内部键为 `(AccountContext,gid,waiting_round_id)`，其中 round 与起始消息及版本关联。用户隐藏记录只绑定该 round/version，不永久忽略整个会话。

## 5. 计时、恢复与一致性

以服务器消息时间和已验证服务器时间差建立锚点，再用单调时钟推进；时钟偏差/锚点失效时显示估计或待核对，不显示平台考核倒计时。

Rust 维护期限队列；只在需要展示时以 1 Hz 更新数字。主窗口最小化不停止计时。机器睡眠、网络断开、流跳号、服务端状态过旧时进入 `reconciling/stale`：保留未确认完成的等待，暂停新弹窗与声音，先补偿消息和刷新会话，再重算超时条目。不能仅因这次响应未含某会话就清掉提醒，必须区分增量与完整快照。

重启后恢复最小 round/隐藏信息，但在当前身份与服务端事实重新核对前不补响；超过阈值的现存轮次核对后最多提醒一次。注销或身份替换清除对应展示并拒绝迟到回调。

## 6. 独立窗口及操作

Tauri 本地窗口标签 `alarm`，内容只来自 Rust 快照。窗口需要：单例、置顶、不激活显示、可滚动列表、关闭时隐藏、点击定位正确会话。位置默认在可用工作区右下，显示器变化后约束到可见范围。

2026-11-04 调整：布局改为紧凑列表，取消顶部大块客户信息和底部操作栏。每行显示脱敏名称、等待时长、清除和最多 3 行消息预览，行高随预览变化；两条及以上时页头提供“全部清除”。窗口高度跟随内容（`notify_alarm_resize`），从所在角向上增长，超过工作区 60% 时列表滚动。列表为空时窗口一律隐藏，无论它是由引擎还是主窗按钮打开的；宿主调度线程每秒核对一次。

消息预览是有意放开的例外，用户知情地选择了在置顶窗显示客户正文：预览取宿主内存展示缓存里的会话列表预览，发送快照前才附加，单行化并限 200 字。`core-notify` 的快照和持久化轮次仍不含正文，日志同样不含（`AlarmEntryDto` 的 `Debug` 只输出有无预览）。

2026-11-04 起 `notice` 浮窗适用同一例外：`notify://notice` 定向发给 `notice` 窗，携带客户名称和预览，事件结构不实现 `Debug`。消息事实和展示行是两路没有固定顺序的 IPC，所以只有展示行时间不早于该会话最新客户消息时才带预览，否则先显示名称和“发来一条新消息”；展示行随后到达时由 `notify://notice-update` 原地补全，不新增卡片、不重置计时，也不用空值覆盖已显示的内容。补全只在卡片弹出后停留时长再加 4 秒内进行，且按账号代次匹配。

设计命令限于 `snapshot`、`open_conversation`、`hide_round`、`set_enabled`、`set_threshold`、`set_sound_enabled`；每次操作都验证来源窗口、身份和提醒版本，不提供发送消息、结束会话或任意 URL 命令。具体签名在原型后冻结。

点击“打开会话”激活 main，通过已有会话身份定位；失败显示原因并保留提醒。窗口不直接写已读或自动回复。锁屏期间隐藏客户内容、停止声音，解锁先对账。

## 7. 原型与验收

| 项目 | 必须验证的结果 |
| --- | --- |
| 30 秒等待 | 受控客户消息产生一个窗口条目；不依靠隐藏网页里的定时器维持计时 |
| 连续与重复消息 | 最早未回复时间不后移；重复、重放和两条连接的同一消息只算一次 |
| 回复及失败 | 已读/点击发送/失败/unknown 不清除；确认有效商家回复后清除 |
| 多角色与会话状态 | 机器人及系统消息不误清除；结束/转出以回读为准；未知角色先核对 |
| 窗口 | 主窗口隐藏、最小化时仍可显示 alarm；显示不夺取输入焦点，点击才导航；多条消息复用同一窗口 |
| 关闭与隐藏 | 只隐藏当前 round/version；不伪造已回复；新有效客户消息可重新提示 |
| 断网、睡眠与重启 | 恢复先补偿与刷新，不拿旧会话补响或遗漏别端已回复事实 |
| 旧身份回调 | 注销/换身份后不能显示旧客户或跳到错误会话 |
| 资源与声音 | 没有新增 SDK 连接/提醒轮询；L3 每轮最多一次超时音；L4 仅在开启后 15 秒循环、10 分钟封顶 |
| 升级 | L3→L4 只置顶一次 |

Windows/WebView2 先做可运行原型，记录宿主和运行时版本、实际事件样本与窗口视频/截图；macOS 未通过同样的焦点和后台矩阵前不宣称支持。受控验收使用测试会话，不能通过向真实客人发送试验消息来造结果。
