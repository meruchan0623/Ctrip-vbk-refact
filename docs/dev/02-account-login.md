# 02 网页登录与身份边界

2026-10-30。沿用目标网页的登录、验证和失效流程；不重建桌面账号管理。

1. 网页登录交互在受隔离的浏览器会话中完成，不提取密码或把 Cookie 复制到普通业务库。
2. 读取当前服务端用户与客服身份后建立 `AccountContext`，不得用可重名昵称定位会话。
3. 登录失效、注销或身份替换推进 `session_generation`，撤销旧连接与提醒，拒绝旧代次响应。重新登录先同步会话事实，再恢复提醒。
4. 客服在线/挂起/离开/下班属于网页业务状态，与登录和网络状态分开；切换后按网页接口回读，不因断线自行改为下班。
5. 默认只覆盖当前登录身份。不安排多账号桌面标签、旧 Electron 账号/密码迁移或自建 ticket 续期端点。

`AccountsMobileRequestFilterException` 等错误以具体网页契约识别；普通网络失败不等于认证过期。验证码和实名验证沿用官方流程，不绕过。

登录与角色设置依据：[网页调查](../research/2026-10-30-web-im-observation.md)、[客服状态调查](../research/2026-10-30-agent-status-and-settings.md)。后者含桌面静态材料，仅已由目标网页确认的部分进入开发。旧设计见[归档](../archive/desktop-baseline/dev/02-account-login.md)。
