# 10 网页 IM 与强提醒事实接缝

2026-10-30。以[范围决定](../decisions/2026-10-30-web-only-scope.md)和目标网页真实入口为准，不再以桌面包功能表逐项移植。

## 网页已有功能

消息/会话列表、历史与补偿、发送/回执/已读、通知、网页个人设置，以及实际开放的成员操作、评价、星标、附件和翻译控件，均按具体网页版本、角色和动态契约验证。静态发现但界面未开放的能力不自动启用。

订单主动联系使用“详情 → IM 联系”，网页订单号搜索只承诺已验证的已有会话路径。参数和返回以[实测](../research/2026-10-30-web-order-conversation.md)为准，不能自拼客户身份。

## 会话列表

- 选项卡只有“处理中 N”“已完成 N”两项，与官方网页一致；不做星标。
- 右键会话（官方已有操作）：
  - **置顶 / 取消置顶**：置顶会话排在列表最前。官方网页按本地会话存储的 `isTop` 处理，见[接口复查](../research/2026-10-30-missing-apis.md)；不承诺跨设备同步。
  - **标记会话颜色 / 取消标记**：给会话打颜色标记，列表项左侧显示色条。原型暂用红、橙、黄、绿、蓝、紫六色。官方的颜色选项、存储位置（本地或服务端）和接口尚未抓包，实现前需在官方网页实际操作一次并记录请求与读回，再对齐颜色和保存方式。
- 标记与置顶只影响展示和排序，不改变会话状态、未读数或强提醒等待轮次。

## 传输与状态

使用网页 Web IM SDK/消息通道和已验证 HTTP 契约；不再安排桌面 Node sidecar、第二套后台连接或 Rust XMPP 重写。网页 WSS 实测不代表脱离原站的 SDK 已验收，独立运行、后台恢复和身份失效必须通过原型。

`confirmed/rejected/unknown` 发送状态分开；未知结果不自动重发。会话动作、回复身份和角色以服务端事实为准；补偿遵循具体方法游标与去重语义，不能只取最大时间后假定已同步完整。

## 独立强提醒接缝

向 Rust 输出身份、代次、消息 ID/时间、角色、服务端确认和会话状态，不输出凭据。初始化/历史重放与实时新消息须区分。强提醒读取同一份会话事实，不另查不存在的“考核时钟接口”。

等待起点、回复清除、隐藏当前轮次及睡眠恢复依照[独立窗口设计](03-strong-alert.md)。没有有效回复证据时，已读和点击发送都不能清掉提醒。

## 完成条件

受控文本收发及回执、未知结果恢复、断线补偿、会话操作权限、网页通知读回、订单联系导航、主窗口隐藏时独立提醒和重新登录后的旧数据隔离均需实测。当前仓库仅有部分网页观测和设计，不作全功能通过承诺。
