# 09 商家助手

保留能力涉及的 TSim 完整方法、Header/Bearer、编码、翻译字段与套餐调用链见[TSim 接口源码契约](../api/external-tsim.md)。这份契约已与当前客户端和拥有方源码对照，线上兼容验证单独标注，不把静态来源当作实测。

2026-10-30。本项目自有能力，保留。

- TSim 登录（不保存密码，凭据存系统凭据库）。
- 翻译服务统一为：**出站（商家 → 客户）固定使用 TSim**，需先登录 TSim；**入站（客户 → 商家）固定使用平台官方翻译**，译文显示在客户原文下方。不提供翻译服务切换。
- 出站翻译：外语会话输入中文后约 0.5 秒生成 TSim 译文预览；客户语言自动识别，可手动改目标语言。
- 发送模式（设置中二选一，界面上需带说明）：
  - **替换草稿**（默认）：译文先在翻译栏预览，点「替换」把输入框内容换成译文，可再修改后手动发送。适合需要核对译文的场景。
  - **直接发送**：按发送键时自动把中文用 TSim 译成客户语言并发出，客户只收到译文，消息下方保留原文供自己核对。适合熟练、追求速度的场景。
  - 两种模式下，译文都绑定会话与草稿版本；草稿改动后需重新翻译，翻译失败时提示「发送原文 / 重试」，不静默发送原文。
- 套餐速览：按消息中的 ICCID/EID 查询套餐、剩余量、供应商/APN、流水号，60 秒内复用结果；右侧栏与订单信息并列显示。
- 套餐速览的补发时间轴（2026-11-04）：订单套餐的 TSim `detail.reissue_list`（`card_dataplan_id` + `create_time` 秒）若非空，宿主逐条读取补发套餐详情，按补发时间升序、剔除自身与已作为订单套餐出现的条目、至多 10 个，经 `plans[].reissues[]`（`{create_time_ms, state: ready|error, info}`）与可选 `order_time`（实时详情 `planTimeLine` 的 order 事件）下发。卡片在该套餐面板顶部画从左到右的「原套餐 → 补发 1 → 补发 2 …」胶囊（标签、`MM-DD HH:mm` 本地时间、状态、剩余量；缺失项省略），参照 TSim 查询窗的补发时间轴。读取失败的补发宽容处理：该项 `state=error`、`info=null`，显示“失败”且不可选，其余照常显示，整次查询不因此失败，也不进入 60 秒复用。点击胶囊只在本地切换面板展示（环、名称、标识、CDR 全部换成所选套餐），不发请求、不注册详情句柄；选中项随会话/订单范围重置，刷新后若失效回到原套餐，标签页与折叠摘要始终显示原套餐。时间轴不带计数图标（数量只进 aria-label）；含补发的卡片展开时高度固定为 440px（仍受 78% 上限约束，内容在卡片内滚动），时间轴轨道固定 38px 高并常驻横向滚动槽，切换套餐/补发或有无滚动条都不会让卡片高度跳动。渲染端对 `order_time`（≤64 字符）与 `reissues`（≤10 项，ready 必带合法投影、error 必须无投影）严格校验，任何一项不合法则整次订单结果按无效处理。
- 订单查询面板（TSim）。
