# 05 最小状态与提醒恢复

2026-10-30。只为当前网页 IM 与独立强提醒保存必要状态，不重建桌面客户端完整数据库。

网页自身的消息存储沿用目标网页行为；若本地重写 IM，缓存和草稿按网页功能实际需要设计。新增提醒状态最小包括身份代次、会话 ID、等待 round/version、可确认的起始消息与时间、已提醒版本和用户隐藏版本。

存储数据按身份隔离；事务提交后才能发布本地新快照。去重键至少含身份与上游消息作用域，不将本地展示序号冒充服务端游标。未知发送结果保留，不能因重启变成待重发。

重启读取的是待核对状态，不能直接弹窗/补响。服务端补偿与会话回读完成后才恢复当前轮次。注销使旧身份状态不可操作，凭据与客户正文不进入诊断日志。

本轮不安排旧 Electron 库导入、全文检索引擎、通用数据库浏览器、全量备份/恢复产品流程。实现细节与存储引擎在原型后确定，避免先造一套旧表结构。

2026-10-30 落盘：`vbk/crates/core-store` 以按 `(environment, account_id)` 命名空间的 JSON 文档（临时文件 + rename 原子提交、损坏隔离为 `*.corrupt-<ts>` 不清空、注销锁只读不删除）实现显式事务与提交事实，仓储含提醒 round、发送意图（unknown 重启后保留且不转待重发）、同步水位（分页断点与完整水位分离）、草稿 CAS、本地置顶；重启读取返回 `PendingVerification`。宿主每次事实泵送后持久化轮次，账号首次推送事实时恢复为待核对。SQLite 等引擎未引入（云检查环境无 crate 注册表），后续可在同一 `Store` trait 下替换。旧设计见[归档](../archive/desktop-baseline/dev/05-store.md)。
